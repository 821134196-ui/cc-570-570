# 门店商品价保申请与差价退款系统

顾客发现活动降价后在订单中申请价保,店员核对规则并退款。系统逐项展示差价计算依据,
支持多次降价只退增量、支付回执幂等、多活动规则版本并存。

## 一条命令启动

```bash
./start.sh
```

启动后访问 **http://localhost:8080**(后端自动建库、迁移、写入演示数据并托管前端)。

- 后端:Rust + Axum + SQLx(SQLite),端口 8080
- 前端:Svelte + Vite,构建产物由后端托管
- 价格与支付接口:本地 mock(`/api/mock/*`)

## 演示流程

界面三个页签:**顾客价保** / **店员复核** / **演示控制台**。
也可以直接运行脚本版完整演示(需服务已启动):

```bash
./scripts/demo.sh
```

推荐手动演示路径:

1. **演示控制台 → ① 降价**:手机 黑色/128G 从 ¥2999 降到 ¥2799
2. **顾客价保 → 张三 → 订单 SO20261003001 → 申请价保**:先试算,页面逐项展示
   计算依据(吊牌价、活动优惠、券抵扣、实付、当前价、当前活动优惠、累计可退、
   已退、本次应退),确认提交
3. **店员复核 → 复核通过并退款**:生成退款单,mock 支付网关返回回执,退款到账
4. **演示控制台 → ③ 重发回执**:同一回执重复送达被忽略,退款金额不变
   (店员页「支付回执投递记录」可见"重复送达,已忽略")
5. **再次降价到 ¥2599 → 再次申请**:只退新增差价 ¥180(累计可退 ¥310 − 已退 ¥130)
6. **演示控制台 → ② 发布新规则版本**(如八五折)→ 再申请:按新版本计算,
   历史退款记录仍保留各自规则版本快照(v1/v1/v2)
7. **拒绝场景**(顾客页直接申请即可看到原因):
   - 订单 SO20261003002:已退货 → 拒绝
   - 李四的订单 SO20260924001:超过 7 天价保期 → 拒绝
   - 手机订单改选「白色 / 256G」规格 → 规格不符拒绝
   - 同一商品重复提交 → 重复申请拒绝

## 计算规则

```
当前有效价格 = 当前吊牌价 × 数量 − 当前活动优惠(按当前生效规则版本)
累计可退差价 = max(0, 原订单实付 − 当前有效价格),封顶为原实付
本次应退     = 累计可退差价 − 此前已退差价
```

- **活动券不重复抵扣**:券已在原订单实付中扣除,计算当前有效价格时不再抵券
- **多次降价**:只退新增部分;已退金额超过按新规则累计可退时,本次为 0
- **规则版本**:申请与退款都记录计算时所用规则版本,历史记录不受新版本影响

## 一致性与幂等设计

| 风险 | 机制 |
|---|---|
| 重复申请 | 部分唯一索引:同一订单明细只允许一个进行中申请(pending/approved) |
| 重复退款 | 退款单幂等键 `refund:{申请号}` 唯一;一申请一退款单 |
| 回执重复送达 | 回执号唯一(部分索引),重复送达只记录痕迹、不变更状态 |
| 重复审核 | 状态机 `pending → approved/rejected → refunded`,条件 UPDATE 守护 |
| 累计退款超限 | 复核时事务内重核:明细级 + 订单级累计退款 ≤ 实付金额 |
| 原订单/历史退款被覆盖 | 订单金额字段创建后无更新路径;退款、回执只追加 |

## 项目结构

```
backend/
  migrations/0001_init.sql   # schema(唯一索引即幂等约束)
  src/calc.rs                # 差价计算纯函数 + 8 个单元测试
  src/service.rs             # 申请/审核/退款/回执幂等核心逻辑
  src/main.rs                # Axum 路由(含 mock 价格/支付接口)
  src/seed.rs                # 演示数据与重置
frontend/
  src/lib/CustomerView.svelte  # 顾客:订单、申请页逐项计算依据
  src/lib/StaffView.svelte     # 店员:复核、退款记录、回执记录
  src/lib/ConsoleView.svelte   # 演示控制台:降价/新规则/重发回执/重置
scripts/demo.sh              # 端到端演示脚本(10 个场景)
start.sh                     # 一条命令启动
```

## 主要 API

```
POST /api/pp/preview            试算(逐项计算依据或拒绝原因)
POST /api/pp/apply              提交申请
POST /api/applications/:id/approve   店员复核通过 → 退款
POST /api/applications/:id/reject    店员拒绝
GET  /api/mock/prices/:sku_id   mock 价格接口
POST /api/webhooks/payment-receipt   支付回执 webhook(幂等)
POST /api/mock/receipts/:no/resend   模拟网关重发回执
POST /api/admin/prices          模拟降价
POST /api/admin/rules           发布新规则版本
POST /api/admin/reset           重置演示数据
```
